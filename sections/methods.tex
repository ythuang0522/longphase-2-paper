\subsection*{Overview of \toolname}
\toolname takes as input long-read alignments (BAM or CRAM), a reference genome and heterozygous variant calls, and produces phased VCF files for every variant class together with haplotagged alignments (Fig.~\ref{fig:overview}). The pipeline consists of four sub-commands implemented in a single C++ binary linked against HTSlib\cite{bonfield2021htslib}: \texttt{modcall} identifies allele-specific 5-methylcytosine (5mC) sites from the \texttt{MM}/\texttt{ML} modification tags of the alignments; \texttt{phase} co-phases SNVs, small indels, SVs and 5mC sites in one weighted phasing graph per chromosome and emits per-variant phasing diagnostics; the optional \texttt{gnn} sub-command applies a graph neural network to the diagnostics and removes phase assignments that are predicted to be erroneous; and \texttt{haplotag} assigns each read to a haplotype using the phased variants. A fifth sub-command, \texttt{compare}, implements the evaluation metrics (below). \texttt{phase}, \texttt{modcall} and \texttt{compare} are parallelized over chromosomes with OpenMP; \texttt{gnn} distributes trigger windows over a pool of C++ threads, sharing one immutable copy of the network weights. The graph phasing algorithm extends the design of \longphase~1\cite{lin2022longphase}; the sections below describe the complete current algorithm so that the manuscript is self-contained.

\toolname is a germline, diploid phaser; the somatic setting is outside its scope and is treated in two companion manuscripts from this laboratory that extend the \longphase~1.0 graph to tumour genomes (LongPhase-S\cite{ho2025longphases}, preprint under review; LongPhase-TO\cite{chen2026longphaseto}, manuscript in review). Neither is a dependency of the present work: no code path, trained model, data set or benchmark is shared with them, and none of the results reported here requires either of them. The scope boundary is set out in the Introduction and Discussion.

\subsection*{Input variant calls}
Heterozygous SNVs and small indels were taken from a standard long-read small-variant caller (Clair3\cite{zheng2022clair3} in this study); homozygous and filtered records are carried through to the output unchanged but do not enter the graph. With \texttt{--indels}, small indels were phased alongside SNVs; indels with \texttt{QUAL} below a user threshold (\texttt{--indelQuality}, default 0, i.e.\ disabled) were excluded and marked in the output \texttt{FILTER} column. Each indel was additionally annotated as lying in a tandem repeat, because indel calls in repetitive sequence are the class most often misplaced by the caller and, once misplaced, link the wrong alleles. The test is deliberately narrow: the dinucleotide immediately 3$'$ of the indel position is read from the reference and the indel is flagged when that same dinucleotide recurs in five consecutive copies (\texttt{SnpParser::getVariants\_markindel}, \texttt{ParsingBam.cpp}:365--395). Only dinucleotide units are considered; extending the test to trinucleotide units was evaluated during development and did not reduce switch errors consistently across coverages, so it was not adopted. Flagged indels were retained as phasing evidence but cast votes at one-tenth weight (see below), rather than being discarded, so that they can still bridge SNV-poor regions without dominating a contested decision. \todo{An earlier draft described this annotation as ``a repeated unit consistent with the indel length'', which is wrong in both respects: the unit is fixed at 2~bp regardless of the indel length, and five consecutive copies are required. Confirm that the fixed dinucleotide test is intended, since it will not flag an indel inside a homopolymer or a trinucleotide repeat.} SVs were taken from Sniffles2\cite{smolka2024sniffles2} or cuteSV\cite{jiang2020cutesv} run with read-name reporting (\texttt{--output-rnames} or \texttt{--report\_readid}); homozygous SVs, SVs whose breakpoint coincides with an SNV, and SVs with duplicated positions were excluded. For each retained SV we recorded the set of supporting read names and the SV length.

\subsection*{Calling allele-specific methylation (\texttt{modcall})}
Base-level modification probabilities (Supplementary Fig.~9) were read from the \texttt{MM}/\texttt{ML} tags produced by Dorado\cite{ont2025dorado} (or the PacBio equivalent) and carried into the alignments by \texttt{minimap2 -y}\cite{li2018minimap2}. For each CpG on each read, the base was labelled methylated if the modification probability was $\ge 0.8$ (\texttt{--modThreshold}) and unmethylated if it was $\le 0.2$ (\texttt{--unModThreshold}); intermediate values were treated as noise. Reads on the reverse strand were mapped to the forward-strand CpG coordinate and the two strands of each CpG were genotyped jointly. Each read was thereby assigned to one of three states at the site, and a site was called heterozygous (allele-specifically methylated) when the two states were balanced and the ambiguous fraction small:
\begin{equation}
\frac{\min(M_R,U_R)}{\max(M_R,U_R)} \ge 0.6 \;\;(\texttt{--heterRatio}),
\qquad
\frac{A_R}{M_R+U_R+A_R} \le 0.2 \;\;(\texttt{--noiseRatio}),
\label{eq:hetmeth}
\end{equation}
where $M_R$, $U_R$ and $A_R$ are the numbers of methylated, unmethylated and ambiguous reads; otherwise the site was called homozygous methylated or unmethylated and excluded from phasing. Only CpG dinucleotides were considered; modification calls at non-CpG cytosines were discarded.

A site passing equation~(\ref{eq:hetmeth}) is balanced but not necessarily allele-specific, because a site at which methylation varies stochastically between reads satisfies the same inequalities. Candidate sites were therefore required to co-segregate with a neighbouring heterozygous marker. Writing $RR$, $RA$, $AR$ and $AA$ for the numbers of reads carrying each of the four combinations of the two states at a pair of sites, a pair was accepted as linked when
\begin{equation}
\frac{\max(RR+AA,\; RA+AR)}{RR+AA+RA+AR} \ge 0.9 \;\;(\texttt{--connectConfidence}),
\label{eq:linkmeth}
\end{equation}
that is, when nearly every read supports one of the two possible pairings rather than a mixture. Equation~(\ref{eq:linkmeth}) is not merely analogous to the phasing graph but identical to it: the implementation calls the same \texttt{VariantEdge::findNumberOfRead} routine (\texttt{PhasingGraph.cpp}:230--238), which returns the pair $(P,Q) = (w_{rr}+w_{aa},\, w_{ra}+w_{ar})$, and evaluates $\max(P,Q)/(P+Q)$. The two methylation states therefore enter the graph on exactly the same footing as reference and alternate alleles, which is what allows \texttt{phase} to co-phase them without methylation-specific machinery.

Linking was applied in two modes. In \emph{SNV-anchored} mode, used whenever an SNV VCF was supplied, a candidate CpG was accepted as a strong anchor if it satisfied equation~(\ref{eq:linkmeth}) against an SNV among the next 20 variants (\texttt{--connectAdjacent}). In \emph{methylation-only} mode, used where no informative SNV is in range --- precisely where methylation is most valuable for bridging --- the same criterion was applied between two candidate CpGs. In both modes a pair was considered only while the number of reads spanning it exceeded $\max(6,\,(n_1+n_2)/4)$, where $n_1$ and $n_2$ are the numbers of reads recorded at the two sites; a pair falling to or below that bound terminates the neighbour scan for the current site rather than merely being skipped, so that support is never accumulated across a sparsely covered gap (\texttt{ModCallParsingBam.cpp}:872--912). Candidates never satisfying equation~(\ref{eq:linkmeth}) were held back as weak points and admitted only if they satisfied it on at least six reads against an already accepted CpG, in an iterative expansion of two rounds (\texttt{--iterCount}, default 2; lines 1040--1075).

Finally, runs of consecutive CpG coordinates were merged into a single locus represented by the first position. This is not a cosmetic simplification. 5mC is called on one strand at a time, so a CpG contributes methylated reads on the forward strand and unmethylated-looking reads on the reverse; merging consolidates both strands of a run into one locus carrying one read list, which removes the need for \texttt{phase} to reason about strand at all and lets methylation loci be voted on concurrently with SNVs by the unmodified graph algorithm. Consecutive CpG positions (adjacent coordinates) were merged and represented by their first position. The resulting VCF records the methylated and unmethylated read names (\texttt{MR}, \texttt{NR}), the read strand and the per-site depths, and is passed to \texttt{phase} through \texttt{--mod-file}.

\subsection*{Extraction of read-level allele observations}
For each chromosome, all alignments with mapping quality $\ge 1$ (\texttt{--mappingQuality}) that were not unmapped, secondary or marked as optical/PCR duplicates were streamed once and, for every variant they overlap, converted into an allele observation with an associated quality. Supplementary alignments were deliberately retained as phasing evidence (\texttt{ParsingBam.cpp}, \texttt{BamParser::isValidAlignment}, lines 945--961), which is why the overlapping-alignment filter below is required; this differs from the stricter filters applied inside \texttt{modcall} and \texttt{haplotag}. SNV alleles were read from the aligned base and inherit its Phred base quality. Insertion and deletion alleles were called from the CIGAR string: a read supports the ALT allele if a CIGAR insertion or deletion begins immediately after the variant position, and the REF allele otherwise; when a read deletion spans an SNV in a homopolymer of length $\ge 3$, the SNV allele was recovered from the base following the deletion. SV alleles were assigned by scanning a window of 20 CIGAR operations (\texttt{--svWindow}) around the SV start for an insertion or deletion whose length is within 10\% of the SV length (\texttt{--svThreshold}); reads listed by the SV caller as supporting the SV were also assigned the ALT allele. 5mC alleles were taken from the \texttt{modcall} read lists (methylated~$=$~allele~0, unmethylated~$=$~allele~1) restricted to reads whose strand matched the recorded strand. Soft- and hard-clipping operations longer than 5~bp were counted per reference position, separately for clips at the front (left) and back (right) end of an alignment, as evidence of alignment breakpoints for copy-number detection (below).

Three filters were applied before graph construction. (1)~\textit{Homopolymer SNV filter}, applied under \texttt{--ont} only (\texttt{PhasingProcess.cpp}:122, \texttt{if(params.isONT)}; \texttt{SnpParser::filterSNP}, \texttt{ParsingBam.cpp}:583--648): when two SNVs both lie in homopolymers of length $\ge 3$ and are $\le 2$~bp apart, the downstream SNV was removed, because such pairs are dominated by systematic homopolymer-length errors in nanopore reads. (2)~\textit{Overlapping-alignment filter}: when two alignments of the same read overlapped by more than 20\% of their combined span (\texttt{--overlapThreshold}), the shorter alignment was discarded. (3)~\textit{Copy-number-aware filter} (Supplementary Fig.~4). Collapsed paralogues and copy-number-altered segments recruit reads from more than one locus, so that paralogue-specific differences are called as heterozygous variants and link alleles that are not on the same chromosome. Such segments are bounded by alignment breakpoints, and the two boundary shapes they produce were detected from the per-position front- and back-clip counts by a finite-state scanner with two entry conditions. A \emph{step} boundary, characteristic of a copy-number transition, was declared when $\ge 5$ front-clips occurred at a single position; a \emph{ramp} boundary, characteristic of the progressively nested breakpoints left by breakage--fusion--bridge cycles, was declared when front-clips merely exceeded back-clips at a position without reaching that threshold. In both states the scanner carries a running excess $c$ of front- over back-clips and extends the candidate end by a 30~kb look-ahead while $c > 30$. A step interval was closed when the back-clip count at a position reached an adaptive pull-down threshold --- $n/2$ where $n$ is the front-clip count that opened the interval, when $n \ge 10$, and 5 otherwise --- or when $c$ decayed to an adaptive floor (5 for $n \ge 20$, $n/4$ for $10 \le n < 20$, and 2 for $n < 10$). A ramp interval was closed when the back-clip count reached $c/4$ (or 5 while $c \le 20$), so that the gradual accumulation is terminated by the drop that ends it. Candidates exceeding 200~kb, or in which $c$ fell to zero, were abandoned.

Within each interval, every read was scored by its \emph{mismatch load} $R_m$, the number of heterozygous sites inside the interval at which the read carries the alternate allele, and every heterozygous variant $v$ in the interval was then scored by
\begin{equation}
\mathrm{MR}(v) = \frac{\bar{R}_m^{\,\mathrm{ALT}}}{\bar{R}_m^{\,\mathrm{REF}} + \bar{R}_m^{\,\mathrm{ALT}}},
\label{eq:cnvmr}
\end{equation}
where $\bar{R}_m^{\,\mathrm{ALT}}$ and $\bar{R}_m^{\,\mathrm{REF}}$ are the mean loads over the reads supporting the alternate and the reference allele of $v$. Variants with $\mathrm{MR}(v) \ge 0.7$ were removed from all reads. The statistic separates the two cases that matter: at a genuine heterozygous site both allele populations are ordinary reads of the locus and carry comparable loads, so $\mathrm{MR} \approx 0.5$, whereas at a paralogue-specific difference the alternate allele is carried by reads that originate elsewhere and therefore mismatch the reference at many other sites in the same interval as well, driving $\mathrm{MR}$ towards~1. A variant was scored only when both means were non-zero, so that sites at which one allele population carries no other alternate allele at all are never removed on this basis. Equation~(\ref{eq:cnvmr}) and the 0.7 threshold are implemented in \texttt{VairiantGraph::calculateCnvMismatchRate} (\texttt{PhasingGraph.cpp}:519--557, test \texttt{variant.allele == 1} at line 550), \texttt{calculateAverageMismatchRate} (lines 605--642) and \texttt{filterHighMismatchVariants} (lines 645--690); the two-state scanner is \texttt{Clip::getCNVInterval} (lines 1128--1229) with the adaptive thresholds set in \texttt{Clip::updateThreshold} (lines 1112--1127). \todo{An earlier draft called the per-read score ``mismatches to the phasing graph'', which was wrong; it is the count of alternate alleles the read carries inside the interval, i.e.\ its mismatch load against the reference, and the text and Supplementary Fig.~4 now say so. \subsection*{Weighted phasing graph}
Each heterozygous variant $v$ contributes two nodes (Supplementary Figs.~1--3), $v^{\mathrm{ref}}$ and $v^{\mathrm{alt}}$. For every read, the observed alleles were sorted by position and each allele node was connected to the allele nodes of the next $k = 35$ variants on the same read (\texttt{--connectAdjacent}), provided the two variants were within 300~kb (\texttt{--distance}). Each read contributes a weight of 1 to the edge if both of the two observations have Phred quality $\ge 12$ (\texttt{--baseQuality}) and a weight of 0.1 (\texttt{--edgeWeight}) otherwise. SV observations from the caller's read list were given a fixed high quality, whereas reads not listed by the caller were treated as REF with a lower quality; 5mC and indel observations were given a fixed high quality. For a pair of variants $(u,v)$ this yields four accumulated weights $w_{rr}, w_{ra}, w_{ar}, w_{aa}$, the total support for the two allele pairings $P = w_{rr}+w_{aa}$ (\textit{cis} between reference alleles) and $Q = w_{ra}+w_{ar}$, and their similarity $s = \min(P,Q)/\max(P,Q)$.

\subsection*{Haplotype resolution by multi-neighbour voting}
Variants were processed in coordinate order. For the current variant $u$, each of its $k$ downstream neighbours $v$ received a vote for the pairing with the larger support ($P$ versus $Q$). A pair was declared uninformative and cast no vote if $s > 0.7$ (\texttt{--edgeThreshold}); for SNV--5mC pairs the threshold was 0.3, and such pairs cast no vote at all when their total accumulated support was below 1. Votes were weighted: 1 by default; 20 when the pairing was near-unanimous ($s \le 0.1$ with total support $\ge 1$, or one pairing accumulated less than 1 unit of support while the other accumulated at least 1); and 0.1 when the voting variant was a tandem-repeat indel. The vote was translated into a haplotype vote for $v$ using the already assigned haplotype of $u$, and the two weighted haplotype totals $h_1(v)$ and $h_2(v)$ were accumulated from all upstream voters. A guard against a single erroneous ultra-long read counted, among the votes received by $v$, those whose total support was at most 1 read-equivalent; when more than three such votes existed and at least one qualifying vote remained, $h_1$ and $h_2$ were recomputed from only those votes with $s < 0.2$, weight $\ge 1$ and a voting variant that is not a small indel. Variant $v$ was assigned to the haplotype with the larger total. When $h_1 = h_2$ (including the case of no votes at all) and $v$ lay beyond the last position reached by any accepted edge, a new phase block was opened at $v$; a tie at a position already covered by an accepted edge left the previous block intact. Blocks were identified by the position of their first variant, which defines the \texttt{PS} tag.

The constants in this section are not arbitrary. Writing the ambiguity of a pair as $s = \min(P,Q)/\max(P,Q)$, which ranges from 0 for unanimous support to 1 for an even split, the voting rule is a three-level function of $s$: below $\alpha = 0.1$ a pair is treated as near-certain and votes at weight $w = 20$; between $\alpha$ and $\beta = 0.7$ it votes at unit weight; above $\beta$ it does not vote. Each of $\alpha$, $\beta$, $w$, the base-quality threshold $\theta = 12$ and the single-read guard parameters ($N = 3$ votes, ambiguity cut $\mu = 0.2$) was fixed by a sweep on HG002 at 10--60$\times$ before the experiments reported here, and none was re-tuned afterwards. \todo{Add these sweeps as a Supplementary Figure (see Supplementary Fig.~11), and state here that the tuning data are disjoint from --- or, if they are not, that they overlap --- the evaluation data reported in Figs.~2--6. \subsection*{Read-based correction}
After the initial assignment (Supplementary Fig.~5), every read was assigned to a haplotype by weighted majority over its phased alleles, with SNV and SV alleles contributing 1, indel and tandem-repeat-indel alleles 0.1, and 5mC alleles nothing; a read was tagged only if the majority fraction exceeded 0.65 (\texttt{--readConfidence}) and the total weighted evidence exceeded 1. The allele counts of the two read populations were then used to re-derive each variant's phase: the fraction of tagged reads consistent with the assignment $\rho = \max(n_1, n_2)/(n_1+n_2)$, where $n_1$ and $n_2$ count haplotype-1 reads carrying the reference allele plus haplotype-2 reads carrying the alternate allele and vice versa, had to exceed 0.75 (\texttt{--snpConfidence}); otherwise the variant was left unphased. This second pass removes assignments driven by a small number of chimeric or mis-mapped reads.

\subsection*{Phasing entropy and graph export}
For each phased variant we recorded the two weighted haplotype totals $h_1$ and $h_2$ (after the single-read guard, where it fired) and their normalized Shannon entropy
\begin{equation}
\mathrm{PE}(v) = -\sum_{i \in \{1,2\}} p_i \log_2 p_i, \qquad p_i = \frac{h_i}{h_1+h_2},
\end{equation}
which ranges from 0 (unanimous votes) to 1~bit (equal support for both haplotypes), with the convention $0\log_2 0 = 0$. $\mathrm{PE}$ is set to 0 when $h_1+h_2=0$, so a value of exactly 0 denotes either unanimous support or no votes at all; the two cases are distinguished by \texttt{H1}$+$\texttt{H2}. \todo{The Results section interprets $\mathrm{PE}=0$ as ``unanimous but sparse votes''. State explicitly there, or add a supplementary panel, what fraction of the $\mathrm{PE}=0$ variants had $\texttt{H1}+\texttt{H2}=0$, since those carry no vote evidence at all rather than unanimous evidence.} $\mathrm{PE}$, $h_1$ and $h_2$ are written to the output VCF as the \texttt{INFO} fields \texttt{PE}, \texttt{H1} and \texttt{H2}. With \texttt{--dot}, the per-chromosome phasing graph is written in DOT format as \texttt{<prefix>.<chrom>.dot}, one directed edge $u^{a}\rightarrow v^{b}$ per accepted voting pair with the haplotype weight accumulated at $u$ at the time the vote was cast as label; these files are the input of the GNN module.

\subsection*{Graph neural network for phase-error detection}
The GNN operates on local windows of the phasing graph and predicts, for each variant, the probability that its phase assignment is wrong (Supplementary Figs.~6--8). Only records that are heterozygous and phased in the input VCFs enter the module. Variant records from the SNV/indel, SV and 5mC VCFs were merged and sorted by position so that windows span all co-phased variant classes, and a window was opened around every such variant with $\mathrm{PE} \ge 0.8$ (\texttt{--pe-threshold}), extending 20 variants (\texttt{--window}) on each side of the trigger in that merged list. A window therefore contains at most $2\times 20 + 1 = 41$ variants and $82$ allele nodes. Windows with more than 256 nodes are skipped; at the default window size this cap is never reached and it binds only for \texttt{--window} greater than 127.

\textit{Node features.} Each allele node carried 31 features in four groups (Supplementary Tables~1 and~2; architecture in Supplementary Table~3 and Supplementary Fig.~7). \emph{Phasing evidence}: $\mathrm{PE}$; the allele's genotype index; the reference and alternate genotype indices; whether the variant is the window trigger; whether it shares the trigger's phase set; the allele index; the signed position offset from the trigger normalized by the largest absolute offset in the window; $h_1$, $h_2$, $h_1+h_2$, the vote ratio $\max(h_1,h_2)/(h_1+h_2)$; $\log_2(1+h_1+h_2)$, $\ln(1+h_1)$, $\ln(1+h_2)$; and $\log_2$ of the total vote weight divided by its mean over the 21 variants centred on the variant. Here $h_1$ and $h_2$ were taken from the first outgoing DOT edge of each allele when one existed and from \texttt{INFO/H1}, \texttt{INFO/H2} otherwise. (Feature indices, logarithm bases and the code order of the graph-structure features were verified against \texttt{GNNProcess.cpp}:427--461 at commit cc17fb1; Supplementary Table~1 lists them by group.) \emph{Genomic context} (computed from the reference when \texttt{-r} is given, and zero otherwise): homopolymer length at the variant (capped at 20); GC content in $\pm 50$~bp; the longest tandem-repeat unit count with unit size 2--4 in $\pm 15$~bp, divided by 10 and capped at 1; Shannon entropy of the $\pm 15$~bp sequence; the number of variants within $\pm 500$~bp, minus one and divided by 20; and $\log_{10}(1+d)$ for the distance $d$ to the nearest indel, capped at $\log_{10}(10001)$. \emph{Graph structure}: the number of distinct target positions of the variant's outgoing DOT edges, divided by 10 and capped at 1; $\ln(1+n_{\mathrm{PS}})/\ln(101)$ for the number $n_{\mathrm{PS}}$ of variants in the variant's phase set; $\log_{10}(1+|\text{offset}|)$ from the trigger; the standard deviation of the variant's outgoing DOT edge weights, divided by 100 and capped at 1; and an indicator of whether the variant is a bridge vertex, i.e.\ whether deleting it increases the number of connected components of the position-level, undirected window graph. \emph{Variant class}: four one-hot indicators (SNV, indel, SV, 5mC), the SNV/indel distinction being made on $|\,|\mathrm{ALT}|-|\mathrm{REF}|\,|>0$.

Each edge carried six features: the logistic-transformed vote weight $1/(1+e^{-w})$; $\log_{10}(1+\text{genomic distance})$; $\ln(1+w)$; whether the two endpoints carry the same allele index; whether the two variants belong to different phase sets; and $w$ divided by the total outgoing weight of the source allele node within the window. \todo{Earlier drafts glossed the fourth feature as ``whether the two alleles are on the same haplotype''. \textit{Architecture.} The network follows the general, powerful, scalable (GPS) graph-transformer recipe\cite{rampasek2022gps}. Node features were standardized with a batch-normalization layer\cite{ioffe2015batchnorm} whose statistics are frozen at inference, linearly projected to a 128-dimensional embedding and passed through a GELU non-linearity\cite{hendrycks2016gelu}. Four identical layers then each combine a local and a global branch. The local branch is a four-head GATv2 message-passing layer\cite{velickovic2018gat,brody2022gatv2} in which the attention logit of head $t$ for edge $j \rightarrow i$ is
\begin{equation}
\alpha^{(t)}_{ij} \;\propto\; \exp\!\Big(\mathbf{a}_t^{\top}\,\mathrm{LeakyReLU}_{0.2}\big(\big[\mathbf{W}_r \mathbf{x}_i + \mathbf{W}_l \mathbf{x}_j + \mathbf{W}_e \mathbf{e}_{ij}\big]_t\big)\Big),
\end{equation}
where $[\cdot]_t$ selects the 32 coordinates of head $t$, $\mathbf{W}_e$ is a per-layer edge encoder without bias and the normalization is a softmax over the incoming edges of $i$ (a node with no incoming edge instead receives the uniform average of $\mathbf{W}_l\mathbf{x}_j$ over all window nodes); the head outputs are concatenated and a bias is added. The global branch is four-head scaled dot-product self-attention over all nodes of the window\cite{vaswani2017attention}, with no masking. The two branch outputs are added to the residual stream, followed by layer normalization\cite{ba2016layernorm}, a two-layer feed-forward block (128$\rightarrow$256$\rightarrow$128, GELU) with a second residual connection and layer normalization. The final node embedding is concatenated with two edge-context scalars, the sum and the non-negative maximum of the raw weights of the node's incoming edges excluding its self-loop, and passed through a two-layer classifier (130$\rightarrow$128$\rightarrow$2) with softmax output.

The model comprises 687,358 float32 values (2,749,432~bytes), namely 124 in the input batch-normalization layer (scale, shift and the two frozen running statistics over 31 features), 4,096 in the input projection, 166,528 in each of the four GPS layers, and 17,026 in the classifier. Inference is implemented in plain C++ with dense $N\times N$ adjacency and edge tensors and no external runtime dependencies; the exact erf-based GELU must be used, because the tanh approximation changes the output by $\sim 10^{-3}$ and does not reproduce the reference implementation. Predictions for the two allele nodes of a variant were averaged. Only variants in the central zone of each window were retained, that is those whose normalized absolute offset $r$ from the trigger satisfies $r \le \min\!\big(1,\,10/\max(1,\mathrm{round}(20\,r_{\max}))\big)$, where $r_{\max}$ is the largest normalized absolute offset in the window; because offsets are normalized by that same largest offset, $r_{\max}=1$ for every window containing a variant more than 1~bp from the trigger, so in practice the retained zone is the central half of the window's genomic span. A variant covered by several windows received the running mean of its predictions. \todo{Two points on the central-zone rule, verified at \texttt{GNNProcess.cpp}:517--531. (i) The code uses \texttt{std::round}, not the ceiling that earlier drafts wrote; corrected above. (ii) Because $r_{\max}\equiv 1$ in essentially every window, the expression collapses to the constant 0.5 and the $r_{\max}$ dependence is dead. \textit{Correction.} A variant whose mean predicted error probability was $\ge 0.30$ (\texttt{--break-threshold}) was unphased: its genotype was rewritten in unordered, ascending form (\texttt{0|1} and \texttt{1|0} both become \texttt{0/1}) and its \texttt{PS} tag was removed, while the pair of alleles was preserved and no genotype was ever flipped. Bridge vertices may optionally be protected (\texttt{--respect-bridge}; off by default). After unphasing, the remaining phased variants of each phase set were checked for connectivity through the surviving DOT edges; when a phase set became disconnected, the largest component kept the original \texttt{PS} and every other component received a new \texttt{PS} equal to the 1-based position of its first variant (\texttt{--no-split-blocks} disables this). The corrected SNV/indel, SV and 5mC VCFs are written separately, as \texttt{<prefix>.vcf}, \texttt{<prefix>\_SV.vcf} and \texttt{<prefix>\_mod.vcf}.

\subsection*{Haplotagging}
Reads were assigned to haplotypes by \texttt{haplotag}, which counts, for each primary (optionally supplementary, \texttt{--tagSupplementary}) alignment with mapping quality $\ge 1$ (\texttt{--qualityThreshold}), the phased SNV, indel, SV and 5mC alleles it carries on each haplotype and tags the read with \texttt{HP:i:1} or \texttt{HP:i:2} and the phase set \texttt{PS} when the majority haplotype accounts for at least 60\% of the informative alleles (\texttt{--percentageThreshold}); reads without a clear majority are left untagged. SV alleles were re-derived from the CIGAR string with the same window and length tolerance as in \texttt{phase}. Tagging can be restricted to a region (\texttt{--region}) and a per-read log can be written (\texttt{--log}). Output can be written as BAM or CRAM (\texttt{--cram}).

\subsection*{Evaluation metrics}
Metrics (Supplementary Fig.~10) were computed with \texttt{longphase compare}, a C++ re-implementation of the \texttt{whatshap compare} algorithm\cite{martin2016whatshap} that is parallelized over chromosomes with OpenMP. For each chromosome, heterozygous variants common to the truth and query VCFs were intersected by position and alleles and partitioned into blocks that are phased in both files; singleton blocks were ignored. Within each block the query haplotype string was compared with the truth string in switch encoding (the sequence of relative phase changes between consecutive variants), giving the number of \emph{switch errors}; the \emph{switch error rate} is the number of switch errors divided by the number of assessed variant pairs. The \emph{Hamming distance} is the block-wise minimum over the two possible haplotype orientations of the number of misassigned variants, summed over blocks and expressed as a percentage of compared variants. Switch errors were further decomposed into isolated switches and flips (two consecutive switches). The \emph{phased fraction} is the number of truth heterozygous variants phased by the query divided by the total number of truth heterozygous variants, reported separately for SNVs, indels, SVs and 5mC sites; the \emph{block N50} is the span-weighted median block length of the query over all chromosomes. Switch-error rates and Hamming distances for cross-tool comparisons were computed on SNVs only, so that the co-phasing of additional variant classes did not change the evaluated set. Switch-error positions were exported as BED for the analysis of unphased variants, in which each variant unphased by the GNN was classified as absent from the benchmark, homozygous in the benchmark, or a true heterozygous site, and cross-tabulated by read depth and phasing informativeness. \todo{Required for the claim that \texttt{longphase compare} ``yields identical values'' to \texttt{whatshap compare}: report the concordance explicitly (e.g.\ identical switch-error and Hamming counts on all autosomes for all four tools at one coverage, with the \texttt{whatshap compare} version used), in a supplementary table. As previously written the equivalence was asserted without evidence.} \todo{Define the depth and informativeness bins used in Fig.~6b (``low'', ``normal'', ``high'' relative to the genome-wide mean, and the informativeness cut-points) and the ``low genotype quality'' threshold used in Fig.~6c.}

\subsection*{Statistics and reproducibility}
